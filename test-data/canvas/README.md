# Synthetic Canvas calendar-feed fixtures

These small files are self-authored synthetic inputs, not captured user exports and not output generated by Canvas. Every title, date, ID, course label and description is invented. Source links use the reserved `canvas.example.invalid` host: never fetch them. No private feed URL or credential is present. Files use LF line endings for repository readability; tests of strict transport framing can construct CRLF separately. No tests or parser checks were run when creating these fixtures.

## Verified public upstream conventions

Evidence is pinned to Instructure Canvas LMS commit `1c9f0bb8013ed69c4f2efe11fd483025469b7e6c`, discovered through its public GitHub tree. This establishes upstream behavior at that revision, not Sofia's deployed version or the contents of the user's still-unread feed.

- [ICS emitter, `CalendarEvent::IcalEvent`](https://github.com/instructure/canvas-lms/blob/1c9f0bb8013ed69c4f2efe11fd483025469b7e6c/app/models/calendar_event.rb#L768-L890): assignments use `due_at` for both `DTSTART` and `DTEND`; ordinary calendar events use their start/end. Timed values become UTC with seconds set to zero, so the feed is not evidence of source second precision or the original named timezone. All-day items instead have `DTSTART;VALUE=DATE` and **no `DTEND`**, including all-day assignments. Do not manufacture a midnight deadline.
- [Explicit all-day assignment regression specification](https://github.com/instructure/canvas-lms/blob/1c9f0bb8013ed69c4f2efe11fd483025469b7e6c/spec/apis/v1/calendar_events_api_spec.rb#L5695-L5704): assignments due at 23:59 are treated as all-day; date-only output loses that precise clock time. This specification was read, not run.
- The emitter derives UID from class and ID: `event-assignment-ID`, `event-calendar-event-ID`, `event-sub-assignment-ID`. An applied override with an overridden due date replaces it with the override's class/ID, such as `event-assignment-override-ID`. The source `URL` still points to the assignment, and sub-assignment URLs point to the parent. Preserve source UID independently from URL IDs; do not assume they agree or coalesce checkpoints by parent link.
- `SUMMARY` contains the title and appends `[course_code]` when an associated course is found; overrides add an override title and checkpoints can add required-reply wording. There is no separately emitted `CATEGORIES` course record, full course title or guaranteed standalone original assignment title.
- `DESCRIPTION` is plain text derived from HTML, only when allowed; `X-ALT-DESC;FMTTYPE=text/html` can contain the HTML. Treat both as untrusted, and do not render the HTML. `LOCATION` may contain a calendar event's location name/address. Assignment descriptions can be absent legitimately.
- Source URLs are calendar links of the form `/calendar?include_contexts=course_ID&month=MM&year=YYYY#assignment_ID`, not necessarily `/courses/ID/assignments/ID`. Contexts can also be user/group/account. Resolve/allowlist links safely; do not fetch attachments or private URLs found in descriptions.
- `DTSTAMP` comes from `updated_at` rounded down to the minute; `SEQUENCE` is always zero. Content can change without a higher sequence. The emitter does **not** set `STATUS`, `COMPLETED`, `PERCENT-COMPLETE`, `CATEGORIES`, `RRULE` or `RECURRENCE-ID`. It omits an item entirely when no start/due time exists. Calendar-event model/API recurrence fields do not imply an ICS recurrence rule is exported.
- [Public feed selection](https://github.com/instructure/canvas-lms/blob/1c9f0bb8013ed69c4f2efe11fd483025469b7e6c/app/controllers/calendar_events_api_controller.rb#L1226-L1359) applies user-specific assignment overrides, selects a 30-day past/366-day future window, and separately caps queried collections. The public guide's advertised 1,000-item limit must not be mistaken for a completeness guarantee: the inspected code paginates assignments and calendar events separately with `per_page: 1000, max: 1000`. It can include checkpoint and appointment data. A disappeared item does not prove cancellation, deletion, completion or submission; it could fall outside coverage or visibility. The provider-shaped fixtures therefore use absence, not an invented `STATUS:CANCELLED` signal.
- [Feed context lookup](https://github.com/instructure/canvas-lms/blob/1c9f0bb8013ed69c4f2efe11fd483025469b7e6c/app/controllers/application_controller.rb#L1789-L1855), [routes](https://github.com/instructure/canvas-lms/blob/1c9f0bb8013ed69c4f2efe11fd483025469b7e6c/config/routes.rb), and [feed request specifications](https://github.com/instructure/canvas-lms/blob/1c9f0bb8013ed69c4f2efe11fd483025469b7e6c/spec/apis/v1/calendar_events_api_spec.rb#L5627-L5709) establish `/feeds/calendars/user_<opaque-user-UUID>.ics`. Treat the suffix as a secret, not an API access token. A fixed hexadecimal UUID syntax was not established by this research. No example secret is necessary here.

## Files and intended assertions

| File                         | Meaning                                                                                                                                                                                                                                                                                                                                                                                                              |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `original.ics`               | Four provider-shaped VEVENTs: timed assignment `101` due `2026-10-15T18:00:00Z`; ordinary event `201` on October 16 from 16:00–17:30 UTC; all-day calendar event `202` on October 17; date-only assignment override `301` due October 18 linking assignment `102`. Both date-only records omit end. Timed assignment has equal start/end.                                                                            |
| `changed.ics`                | Complete syntactic three-event snapshot: assignment `101` retains UID, changes title/description and moves to October 16 at 18:00 UTC; `201` and override `301` remain; `202` disappears. Sequence stays zero. Re-import must not duplicate stable UIDs; absence means no longer in the imported snapshot, not proven Canvas cancellation. “Complete” here means valid file framing, not complete provider coverage. |
| `unsupported-properties.ics` | Explicitly **non-provider-shaped robustness inputs**: missing DTSTART, finite RRULE, STATUS:CANCELLED, named `America/Los_Angeles` timezone without embedded VTIMEZONE. These are not claims about Canvas exports. If unsupported, disclose/reject/skip according to the adapter contract rather than silently fabricate a deadline or drop recurrence semantics.                                                    |
| `truncated.ics`              | Bounded intentionally malformed response: no closing VEVENT/VCALENDAR. Must not replace a last-success snapshot or trigger absence reconciliation.                                                                                                                                                                                                                                                                   |

`original.ics` exercises escaped comma, semicolon, newline and backslash, a folded description line and folded source URLs. Standard unfolding removes the leading continuation whitespace without adding a new separator. Timed fixture values use UTC (`Z`); they do not claim preservation of the course's timezone. None of the provider-shaped records carry completion state, assignment submission types, grades, action-extraction results or native cancellation flags. Any local completion/action template must remain distinctly local and cannot be written back to Canvas.

For UI/adapter use, retain date kind and precision: assignment due versus ordinary event start/end, and date-only versus instant. Display the native summary rather than guessing a course title or stripping potentially meaningful brackets. Preserve nullable descriptions and source attribution without pretending that every item has all assignment metadata.
